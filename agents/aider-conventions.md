# Aider conventions: Nikita Bier Consumer App Virality Playbook

Use the canonical [`../SKILL.md`](../SKILL.md) when the conversation concerns consumer app growth, virality, activation, onboarding conversion, K-factor, invite flows, friendfinders, share loops, notifications, launch testing, breakout growth, monetization, rumours, platform risk, or AI-era consumer apps.

Location assumption: this conventions file is kept under `agents/`, one level below the repo root. If added to Aider as a read-only conventions file from another location, keep the full repo in context and adjust relative links so `SKILL.md`, `references/`, `templates/`, and `examples/` resolve.

Conventions for playbook work:

1. Read [`../SKILL.md`](../SKILL.md) before answering or editing growth-audit artifacts.
2. Read [`../references/benchmarks.md`](../references/benchmarks.md) before using numbers, metrics, or benchmarks.
3. Read the chapters and templates selected by `SKILL.md` for the user's stage, validation-ladder rung, or special case.
4. Use the audit format specified in `SKILL.md` for finished audits.
5. Cite source IDs from the reference chapters and avoid uncited claims about Nikita Bier.
6. Label repo-authored thresholds, worked examples, and template guidance as "our reading" or "our suggestion" when not directly sourced.
7. Apply the positive-design guardrails in [`../references/12-positive-design-and-guardrails.md`](../references/12-positive-design-and-guardrails.md) to recommendations.

This adapter should stay thin. Do not maintain a second copy of the playbook here; update `SKILL.md`, references, and templates instead.
